## 3. Strict Frontend & UI Design System Rules

Every file under `frontend/components/` and `frontend/app/` MUST obey these rules without exception:

1. **Existing shadcn Primitives ONLY (`@/components/ui/*`)**:
   * Always use `Button`, `ButtonGroup`, `Card`, `CardHeader`, `CardTitle`, `CardDescription`, `CardContent`, `CardFooter`, `Dialog`, `Drawer`, `Alert`, `Badge`, `DropdownMenu`, `Tabs`, `Table`, `Input`, `Textarea`, `Checkbox`, `Switch`, `Select`, `Skeleton`, `Spinner`, `Tooltip`, `Empty`, `Breadcrumb`, `Progress`.
   * Rely on existing component variants (`variant="default" | "secondary" | "outline" | "ghost" | "destructive"`, `size="sm" | "default" | "lg" | "icon" | "icon-sm" | "icon-xs"`).

2. **`globals.css` Semantic Color Tokens ONLY — Zero Hardcoded Colors**:
   * **Forbidden**: `#hex`, `rgb(...)`, `rgba(...)`, `hsl(...)`, `oklch(...)` inline in class strings, Tailwind arbitrary colors (`bg-[#...]`), or literal Tailwind palettes (`bg-white`, `bg-black`, `text-gray-900`, `bg-blue-500`, `text-emerald-400`, `text-slate-500`).
   * **Required**: `bg-background`, `text-foreground`, `bg-card`, `text-card-foreground`, `bg-popover`, `text-popover-foreground`, `bg-primary`, `text-primary-foreground`, `bg-secondary`, `text-secondary-foreground`, `bg-muted`, `text-muted-foreground`, `bg-accent`, `text-accent-foreground`, `bg-destructive`, `text-destructive`, `bg-success`, `text-success`, `bg-warning`, `text-warning`, `bg-info`, `text-info`, `border-border`, `bg-input`, `ring-ring`.
   * **Dark-Mode Contrast Trap**: In dark mode, `--primary-foreground` is a dark tone (`oklch(0.17 0.025 350)`). Never use `text-primary-foreground` on a dark `bg-card` surface — only use `text-primary-foreground` directly on `bg-primary`. On `bg-card`, always use `text-foreground` / `text-card-foreground` and `text-muted-foreground`.

3. **ZERO Comments in UI Files**:
   * Do **NOT** write `// ...`, `/* ... */`, or `{/* ... */}` comments in any `.tsx` UI component file. Code must be self-documenting.

4. **Hugeicons ONLY — Zero Raw `<svg>`**:
   * Import icons exclusively from `@hugeicons/react` (`HugeiconsIcon`) and `@hugeicons/core-free-icons`.
   * Never import `lucide-react`.
   * Never write raw inline `<svg>` elements in feature components (use Hugeicons or CSS `conic-gradient` / shadcn `Progress` / `Spinner`).

5. **DiceBear v10 Avatar Standard (`frontend/lib/profile/avatar.ts`)**:
   * Uses `@dicebear/core` (`Style`, `Avatar`) + `@dicebear/styles`:
     * **User Profile Avatars** (`avatarUriFor`): `voxel-art.json` style.
     * **Project / Canister Avatars** (`projectAvatarUriFor`): `glass.json` style.
   * Never replace project/canister avatars with generic icon placeholders.

6. **Clean Minimalist Visual Hierarchy**:
   * Avoid decorative clutter (e.g., unnecessary status dots next to "CDN Link" headers or redundant leading icons inside multi-line copy dropdown items). Keep cards, badges, and dropdown items clean and minimal.

## 4. Git, GitHub PRs, GitLab Sync & Vercel Deployment Architecture

### 4.1 Dual-Remote Topology (CRITICAL)

This repository has two remotes that serve different roles:

| Remote Name | URL | Role |
|---|---|---|
| **`github`** | `git@github.com:prasangapokharel/ICPay.git` | Primary code hosting, branch protection rulesets on `main` (requires Pull Request, linear history, no force pushes), and PR reviews via `gh pr`. |
| **`origin`** | `git@gitlab.com:prasangapokharel/icpay.git` | **Connected to Vercel's Git Integration.** When Vercel builds `main` (including via Deploy Hook), it clones `gitlab.com/prasangapokharel/icpay` (`Branch: main`). |

### 4.2 End-to-End Release & Vercel Deploy Checklist

Whenever shipping changes to production (`main`):

1. **Stage files explicitly by name** (never `git add -A` or `git add .`).
2. **Check `.gitignore` for `docs/` files**:
   * `/docs/*` is ignored by default in `.gitignore` and selectively re-included via `!/docs/<folder>/` and `!/docs/<folder>/**`.
   * Any new directory under `docs/` (such as `docs/research/` or `docs/memory/`) MUST have explicit negation lines in `.gitignore` or git will refuse to stage it.
3. **Commit on a feature branch** (`feat/...`, `fix/...`, `docs/...`) using Conventional Commits.
4. **Push branch to `github` and open + merge PR**:
   ```bash
   git push -u github <branch-name>
   gh pr create --repo prasangapokharel/ICPay --base main --head <branch-name> --title "..." --body "..."
   gh pr merge <pr-number> --repo prasangapokharel/ICPay --merge --delete-branch
   ```
5. **Sync local `main` and push to `origin` (GitLab) so Vercel has the latest commit**:
   ```bash
   git checkout main
   git pull github main
   git push origin main
   ```
6. **Trigger Vercel Production Deploy Hook** (configured in `.gitlab-ci.yml` under `deploy_vercel`):
   * Always push `origin main` **before** calling the Vercel deploy hook, otherwise Vercel will clone the stale commit from GitLab.

* **Problem**: On the Internet Computer asset canister (`63dke-waaaa-aaaan-q6mvq-cai.icp0.io`), dynamic paths like `/token/[id]` or `/launch/[id]` could not resolve client-side router requests for un-prerendered slugs, causing token detail links to fail on mainnet asset canisters.
* **Solution**:
  * Unified dynamic token links in `TokenCard`, `LaunchPage`, and `PublicTokenCreate` to use `/token?id=${token.id}` (as well as `/launch?id=${token.id}`).
  * Created `frontend/app/(app)/token/page.tsx` with `<Suspense>` handling `searchParams.get("id")`, rendering `LaunchDetail` for creator launch tokens and redirecting to `/wallet?token=${id}` for standard ICRC-1 ledgers.
  * Updated `LaunchPage` (`frontend/app/(app)/launch/page.tsx`) to support `searchParams.get("id")`.
  * Updated `LaunchDetail` (`frontend/app/(app)/launch/[id]/launch-detail.tsx`) to accept `id` prop, check `searchParams.get("id")`, and fallback to `useRewrittenLastSegment()`.
  * Updated `useRewrittenLastSegment()` and `useTokenLedgerId()` in `frontend/lib/routing/rewrittenRoute.ts` to inspect `URLSearchParams` (`id`, `token`, `ledgerId`).
  * Updated `onchain-shell.js` and `vercel.json` rewrites so any direct hard refreshes on `/launch/:id` or `/token/:id` cleanly rewrite to `/token?id=:id`.
